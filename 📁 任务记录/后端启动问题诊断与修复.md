# 🔧 后端启动问题诊断与修复报告

## 问题描述

**症状**:
- Web Dashboard 显示 "后端连接失败 - 使用本地模拟数据"
- Obsidian 插件显示 "未连接"
- Docker 返回 `500 Internal Server Error`

**根本原因**:
Docker Desktop 守护进程出现内部错误，无法正常响应 API 请求。

---

## 已实施的修复

### 1. 路径配置修复 ✅

**问题**: Docker 容器无法访问宿主机的 Vault 路径

**修复**:
- `obsidian_sync.py`: 添加环境变量支持 `VAULT_PATH` 和 `DATA_DIR`
- `docker-compose.yml`: 添加 volume 映射
  ```yaml
  volumes:
    - ~/Desktop/Obsidian/Al-brooks-PA:/vault:ro
    - ~/.ab-console:/data
  environment:
    - VAULT_PATH=/vault
    - DATA_DIR=/data
  ```

### 2. 启动脚本修复 ✅

**新增脚本**:
| 脚本 | 功能 |
|------|------|
| `🔧 修复并启动Docker.sh` | 自动修复并启动完整后端 |
| `🚀 启动完整后端.command` | macOS 双击启动完整后端 |
| `🔧 启动简化后端.command` | macOS 双击启动简化后端 |
| `start-api-gateway-simple.sh` | 简化版后端启动脚本 |

### 3. Obsidian 插件修复 ✅

**修改**:
- `BackendTab.tsx`: 修复脚本执行路径
- 添加新按钮: "🚀 启动完整后端" 和 "⚡ 简化后端"
- 超时时间从 30 秒增加到 120 秒

## Docker 手动修复步骤

如果自动修复失败，请手动执行：

### 步骤 1: 完全退出 Docker
```bash
killall Docker
```

### 步骤 2: 清理 Docker 数据
```bash
# 注意: 这会删除所有容器和镜像
rm -rf ~/Library/Containers/com.docker.docker
```

### 步骤 3: 重启 Docker Desktop
```bash
open /Applications/Docker.app
```

### 步骤 4: 验证修复
```bash
docker ps
docker run hello-world
```

### 步骤 5: 启动后端
```bash
cd ~/Desktop/Obsidian/Al-brooks-PA/AB\ Console-Backend
docker compose up -d
```
