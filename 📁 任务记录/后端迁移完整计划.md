# AB Console 后端迁移完整计划

## 目标
将旧后端（AB Console-Backend-broken）中的 Obsidian 同步功能迁移到新后端（AB Console-Backend），并清理旧资源。

## 迁移内容清单

### ✅ 需要迁移的配置
1. **Obsidian 同步模块** (`obsidian_sync.py`)
   - Vault 路径配置
   - 策略/交易扫描逻辑
   - REST API 端点

2. **Docker Compose 配置**
   - Volume 映射（Vault 路径）
   - 环境变量（VAULT_PATH, DATA_DIR）
   - API Gateway 服务定义

3. **API 路由**
   - `/api/v1/sync/status`
   - `/api/v1/strategies/sync`
   - `/api/v1/strategies`
   - `/api/v1/trades`

### ❌ 不需要迁移的内容
- 旧后端的 config.py（与新后端不兼容）
- 旧后端的 main.py（与新后端架构不同）
- 旧后端的 Docker 配置（使用官方方式）

## 迁移步骤

### Phase 1: 备份与清理（先执行）
1. 备份旧后端的重要配置 ✅ 已完成
2. 停止并删除旧 Docker 容器
3. 删除旧后端目录

### Phase 2: 配置新后端（核心）
1. 检查新后端目录结构
2. 修改 api-service 添加 Obsidian 端点
3. 创建新的 sync-service（独立服务）
4. 更新 docker-compose.yml

### Phase 3: 启动验证
1. 启动 TimescaleDB
2. 启动 api-service
3. 启动 sync-service（如果独立）
4. 验证 API 端点
5. 测试 Obsidian 连接

### Phase 4: 更新前端
1. 更新 Obsidian 插件配置
2. 更新 Web Dashboard API 地址
3. 测试完整流程

## 风险与应对

| 风险 | 概率 | 应对措施 |
|------|------|----------|
| 新后端 api-service 与 Obsidian 模块不兼容 | 中 | 使用独立 sync-service，通过 HTTP 调用 |
| Docker 端口冲突 | 低 | 使用 5434（TimescaleDB）、8088（API） |
| 数据库表结构差异 | 中 | 检查并适配表结构 |
| 路径配置错误 | 中 | 使用绝对路径，验证 Vault 路径 |
