## 升级阶段

### Phase 0: /patrol 技能重构

**目标**：一次性解决环境混乱问题，让每次激活都干净利落

#### 0.1 固化交易环境常量

当前问题：每次激活都要重新确认交易所、API、日志位置。

改为：将所有常量写入 patrol 技能的头部，不需要每次"发现"。

```
交易所: OKX Demo Trading
API Base: http://localhost:8092
Bot ID: claude-pa
杠杆: 125x（OKX demo 默认）
监控列表: BTCUSDT, ETHUSDT, SOLUSDT, BNBUSDT, DOGEUSDT, AAVEUSDT, ADAUSDT, AVAXUSDT

日志位置: AB Console-Backend/data/pa_trader/pa_trader.log
信号格式: [SIGNAL] 📊 CLAUDE [REF: ...]: {分析}
交易格式: [TRADE] 📍 CLAUDE开仓/平仓 {详情}

API 速查:
  持仓:     GET  /positions
  下单:     POST /order
  平仓:     POST /order/{SYM}/close?bot_id=claude-pa
  改止损:   POST /order/{SYM}/modify-sl?new_stop_loss={价}&bot_id=claude-pa
  K线:      GET  /klines/{SYM}/multi
  可交易:   GET  /trading/can-trade/claude-pa
  仓位计算: GET  /trading/calculate-size/claude-pa?entry_price=X&stop_loss=Y&risk_percent=2
  Bot状态:  GET  /trading/bot-summary/claude-pa
```

#### 0.2 简化激活流程

当前 Step 0-1 合并为一个干净的启动：

```
激活 → 并行获取 5 项数据 → 直接进入循环
```

不需要每次"确认环境"，环境是固定的。

#### 0.3 标准化输出格式

每轮循环输出统一格式，不多不少。

### Phase 1: 持仓管理重写

**目标**：从"只有持有/平仓"升级为"完整的持仓生命周期管理"

#### 1.1 持仓管理决策树

```
对每个持仓:
│
├─ 1. Premise 检查
│   ├─ 入场理由是什么？（从交易日志读取）
│   ├─ 当前 PA 是否仍支持这个理由？
│   └─ 出现反向 strong BO / AI 方向切换 → premise 失效 → 离场
│
├─ 2. 止盈检查
│   ├─ 浮盈是否 >= 2R → 平一半
│   ├─ 是否到达 Measured Move 目标 → 减仓
│   ├─ 是否到达 S/R 重合点 → 减仓
│   └─ TC 中的 minor reversal → 不止盈，继续 swing
│
├─ 3. 移动止损
│   ├─ 新 Major HL 确认（做多）→ stop 上移
│   ├─ 新 Major LH 确认（做空）→ stop 下移
│   └─ 判断标准: new HH/LL + failed countertrend BO
│
├─ 4. 状态对应管理
│   ├─ BO/TC → swing 持有，不在 minor reversal 离场
│   ├─ BC → 接近 channel line 减仓
│   └─ TR → 快速止盈，不持有过中间
│
└─ 5. 强制思考
    - "如果现在空仓，我会在这个价格开仓吗？"
    - "对手方被 trap 了吗？还是我被 trap 了？"
```

#### 1.2 止盈规则实现

| 条件 | 操作 |
|------|------|
| 浮盈 >= 2R | 平一半仓位，止损移到保本 |
| 到达 Measured Move | 剩余仓位全部平仓 |
| 到达 S/R 重合（2+ 个 S/R 聚合） | 至少减仓 |
| TC 中 minor reversal | 不止盈 |
| AI 方向切换 | 全部平仓 |

#### 1.3 移动止损实现

```
做多:
  初始 SL = PB 低点 / BO 起点
  新 Major HL 确认 → SL 上移到新 HL 之下
  判断 Major: 之后产生了创新高的 BO

做空:
  初始 SL = PB 高点 / BO 起点
  新 Major LH 确认 → SL 下移到新 LH 之上
```

#### 1.4 入场时记录 Premise

每次开仓必须在日志中记录：
- Premise（为什么做这笔交易）
- 初始 SL 和 TP
- 2R 价格是多少
- Measured Move 目标是多少

持仓管理时读取这些信息，不需要重新分析。

### Phase 2: 强制思考系统

**目标**：用开放问题替代模板化分析，防止偷懒

#### 2.1 开仓前思考（不能复制粘贴回答）

1. "谁在控制市场？证据？"
2. "我在 cycle 的哪个阶段？证据？"
3. "这笔交易失败的话，会发生什么？"
4. "我的 premise 是什么？什么会否定它？"
5. "概率、风险、回报各是多少？"

#### 2.2 持仓中思考（每轮）

1. "Premise 还有效吗？"
2. "现在空仓的话我会开仓吗？"
3. "该止盈了吗？该移止损了吗？"

#### 2.3 复盘思考（每 5 笔交易触发）

1. "最近 5 笔的胜率和盈亏比？"
2. "哪笔偏离了 PA 逻辑？为什么？"
3. "暴露了哪个概念的薄弱？去学哪一章？"

### Phase 3: Token 优化策略

**目标**：减少不必要的 token 消耗，同时避免信息过载影响判断

#### 3.1 当前 Token 浪费点

| 浪费点 | 估算 token | 优化方案 |
|--------|-----------|---------|
| 每次读 3+ reference 文件 | ~6000 | 知识内化到 patrol 技能中，不再每次读文件 |
| 8 品种全部获取 K 线 | ~8000 | 先粗筛（1h 方向 + 波动率），只对有信号的品种读 5m |
| 重复的环境确认 | ~500 | 常量固化，不再每次确认 |
| 冗长的分析输出 | ~2000 | 精简输出，只输出关键判断 |

#### 3.2 分层扫描（减少 K 线读取）

```
第一层: 粗筛（8 品种 × 1h 数据）
  → 只看 AI 方向和波动率
  → 过滤掉 TR/无方向 的品种

第二层: 精筛（通过粗筛的品种 × 多周期）
  → 读 5m/15m K 线
  → 完整 PA 分析

第三层: 深度分析（有信号的品种）
  → 强制思考 5 题
  → Trader's Equation 计算
  → 决定是否开仓
```

预估节省：从每轮 ~16000 token 降到 ~6000-8000 token（无信号时更少）

#### 3.3 知识内化 vs 每次读文件

**原则**：Al Brooks 的核心规则应该内化到 patrol 技能的提示词中，不需要每次读 reference 文件。

只在以下情况读 reference：
- 遇到不确定的概念（比如 Climax 后该不该做）
- 复盘时发现薄弱点，回去学习
- 用户要求学习某个概念

#### 3.4 信息过载防护

读取太多信息会影响判断质量。规则：
- 每轮最多读 2 个 reference 文件
- K 线数据只读有意义的部分（不读 24h 全量）
- 输出要精简：关键判断 + 操作 + 理由，不要长篇大论

- 以 Al Brooks 原课程为准
- 太妃是总结者，可能有遗漏或理解偏差
- 我们自己整理，形成自己的理解

### Phase 5: 复盘机制

**目标**：每 N 笔交易自动反思，持续改进

#### 5.1 触发条件

- 每 5 笔交易（无论盈亏）
- 连续 2 笔亏损
- 单笔亏损 > 2%

#### 5.2 复盘内容

```
复盘报告:
1. 最近 N 笔交易统计（胜率、盈亏比、策略分布）
2. 逐笔回顾:
   - 入场逻辑对不对？
   - 持仓管理做了什么？该做什么？
   - 结果和 premise 一致吗？
3. 薄弱环节识别 → 对应课程章节
4. 下一步改进计划
```

#### 5.3 复盘日志

写入 `data/pa_trader/pa_trader.log`，格式：
```
[REVIEW] 📝 复盘 #{N}: 最近 5 笔 胜率 X% | 盈亏比 X:X | 薄弱: {概念} | 改进: {具体行动}
```
