### P0 — 影响资金安全

#### [ ] Bug #1: position_bot_map 冲突检测用错数据类型

- **严重度**: P0 (可能导致同品种反向仓)
- **文件**: `execution-service/src/__main__.py` 第 324-337 行
- **根因**:
  V3.2 把 `position_bot_map` 的值从字符串 `"al-brooks"` 升级为字典:
  ```python
  # V3.2 新格式
  {"SOLUSDT:USDT": {"bot_id": "al-brooks", "strategy": "double_bottom"}}
  ```
  但 V3.6 新增的冲突检测直接从字典取值，然后和字符串比较:
  ```python
  # __main__.py:328-329 — BUG
  existing_bot = executor._position_bot_map.get(norm_sym)
  if existing_bot and existing_bot != bot_id:  # dict != "trader" → 永远 True!
  ```
  当 `existing_bot` 是字典 `{"bot_id": "al-brooks", "strategy": "..."}` 时，
  `existing_bot != "trader"` 永远为 True，**连同品种同 bot 的正常加仓也会被拦截**。
  更严重的是，如果 `existing_bot` 仍是旧格式字符串 `"al-brooks"`，
  那么 `"al-brooks" != "al-brooks"` 为 False，检测通过 — 行为取决于数据格式混用。

- **影响范围**:
  - 新格式数据: 所有开仓都会被 "品种冲突" 拒绝（包括合法的同 bot 加仓）
  - 旧格式数据: 冲突检测正常但丢失 strategy 归因
  - 两种格式共存时行为不可预测

- **修复方案**:
  ```python
  # 改为使用 accessor 方法
  existing_bot_id = executor.get_position_bot_id(norm_sym)
  if existing_bot_id and existing_bot_id != bot_id:
  ```

- **验证方法**:
  1. 检查 `~/.openclaw/workspace/position_bot_map.json` 当前数据格式
  2. 手动发送两个不同 bot 的同品种信号，确认拦截生效
  3. 手动发送同 bot 同品种信号（加仓场景），确认不被拦截

#### [ ] Bug #3: PNL 单位不一致 — 进化系统数据失真

- **严重度**: P1 (策略权重评估错误)
- **涉及文件**:
  - `order_tracker.py` 第 147-153 行 — 传入**百分比**
  - `executor.py` 第 673-679 行 — 传入 **USDT 金额**
  - `evolution_manager.py` 第 139-141 行 — 累加到 `net_profit`

- **根因**:
  order_tracker 检测止损/止盈时，计算的是百分比:
  ```python
  # order_tracker.py:216-219
  pnl_pct = ((exit_price - entry_price) / entry_price) * 100
  # ...
  pnl=pnl_pct  # 传给 OrderStatusChange
  ```
  然后传给进化系统:
  ```python
  # order_tracker.py:147
  evo.record_trade_result(pnl=change.pnl)  # pnl = 1.5 (代表 1.5%)
  ```
  但 executor 的 close_position 传的是美元:
  ```python
  # executor.py:678
  evo.record_trade_result(pnl=pos.unrealized_pnl)  # pnl = 2.34 (代表 $2.34)
  ```
  进化系统不区分，直接累加:
  ```python
  # evolution_manager.py:139
  sw["net_profit"] = sw.get("net_profit", 0.0) + pnl  # 1.5% + $2.34 = ???
  ```

- **影响范围**:
  - `strategy_weights[*].net_profit` 数据无意义（百分比和美元混在一起）
  - `symbol_preferences[*].net_profit` 同理
  - 策略排名和品种偏好评估不准确
  - 但 `is_win` 判断不受影响（只看正负），所以权重调整（+2/-3）本身还是对的

- **修复方案**:
  统一为 USDT 金额。order_tracker 需要用 数量×价差 而非百分比:
  ```python
  # order_tracker.py — 修改 _determine_exit_reason
  quantity = trade.get("quantity", 0)
  if direction == "long":
      pnl_usdt = (exit_price - entry_price) * quantity
  else:
      pnl_usdt = (entry_price - exit_price) * quantity
  # 同时保留 pnl_pct 用于显示
  ```

- **验证方法**:
  1. 查看现有 `*_evolution.json` 文件中 `net_profit` 的数值范围
  2. 修复后观察新记录的 `net_profit` 是否为合理的 USDT 金额
  3. 考虑是否需要重置历史数据

## 三、架构一致性问题清单

> 这些不是 Bug 但是隐患，逐一排查

#### [ ] 问题 A: 冷却期检查范围不完整

- **文件**: `__main__.py` 第 944-951 行
- **现状**: bot-summary API 只遍历**当前持仓**品种检查冷却:
  ```python
  for p in bot_positions:
      ok, remaining = risk_manager.check_cooldown(bot_id, p.symbol, cooldown_min)
  ```
  但冷却期的意义是"上次交易该品种后等待 N 分钟才能再交易"。已平仓品种的冷却信息不会返回。
- **影响**: signal-router 预注入的状态块中冷却列表可能不完整，agent 无法感知已平仓品种的冷却
- **建议**: 增加一个 API 返回所有冷却中的品种（从 `risk_state.json` 的 `bot_trade_times` 直接计算）

#### [ ] 问题 B: 交易状态双重缓存不同步

- **现状**:
  - `signal-router.js` 的 `canBotTrade()` 用 `current_positions` 缓存值（文件级缓存 10 秒）
  - `__main__.py` 的 `/order` 端点用 `get_positions()` 实时查询币安
- **影响**: router 可能放行了一个信号（认为有空位），但到 `/order` 时实际已满仓
- **结果**: agent 走完分析流程后被 `/order` 拒绝，白白消耗 token
- **建议**: 可接受（router 只是预筛，最终由 /order 把关）。但如果 token 消耗是问题，可以在 router 层也改用实时 bot-summary（已有 10 秒缓存）

#### [ ] 问题 C: 笔记门禁标准不统一

- **现状**:
  - router 消息写: "评分 < 80 或 can_trade=false 时禁止创建笔记"
  - 但 al-brooks 的 `min_score` 默认 70（低于 70 直接不推送），`trade_score` 默认 80
  - 70-79 分的信号会推送给 agent 但不应创建笔记也不下单
  - trader/wyckoff 没有区分推送/交易阈值
- **建议**: 明确三档行为:
  - `< min_score`: 不推送（router 静默过滤）
  - `min_score ~ trade_score`: 推送+Discord 摘要，不下单不建笔记
