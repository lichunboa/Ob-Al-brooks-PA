# V5.0 Agent 驱动架构重构规划

> 生成日期：2026-02-19
> 版本：V5.0 规划稿
> 状态：待执行
> 背景：基于回测分析和系统审计，决定从"信号驱动"转向"Agent 主动分析"架构

---

## 1. 为什么要重构

### 1.1 当前架构的根本问题

经过多轮回测验证（BTC 2020-2021，195K 根 K 线），当前系统存在以下根本矛盾：

| 问题 | 具体表现 | 根本原因 |
|------|---------|---------|
| **信号质量不稳定** | 129 条 TradeCat TA 规则 + PA Engine 混用，逻辑不统一 | 信号来自开源项目改版，非 Al Brooks 体系 |
| **Agent 没有真正理解市场** | Agent 只做"收到信号 → 确认 → 下单"，不做主动判断 | Agent 的角色是执行者而非分析者 |
| **回测持续亏损** | V4 最优：71 笔，PF 0.91，接近盈亏平衡但无法突破 | 双向策略在牛市数据集天然劣势，参数调优到达极限 |
| **知识未内化** | 415 个 Al Brooks 课程文件存在但 Agent 无法有效使用 | 缺乏分层检索机制，每次全读成本过高 |
| **记忆碎片化** | Agent 每次分析都是"新人"，不记得 1 小时前的市场判断 | 无跨 session 市场状态共享机制 |

### 1.2 核心结论

> **当前系统的信号是辅助工具，被错误地用作了决策主体。**
> Al Brooks 的方法论是"先读图判断市场状态，再选择相应策略"，
> 而我们的系统是"先有信号，再让 Agent 确认信号"——顺序颠倒了。

### 1.3 V5.0 目标

- Agent 主动读取 K 线摘要 → 独立判断市场状态 → 选策略 → 决定是否入场
- TradeCat 信号作为**辅助提醒**（触发 Agent 关注某品种），不作为交易依据
- 建立完整的记忆分层系统，Agent 能积累市场经验
- Token 消耗降低 70%+（通过分层检索替代全读）

### 3.2 P0/P1/P2 生命周期

| 级别 | 含义 | TTL | 适用内容 | 存放位置 |
|------|------|-----|---------|---------|
| **P0** | 永不过期 | ∞ | Al Brooks核心原则、四状态框架、风控铁律、品种配置 | `MEMORY.md` |
| **P1** | 长期活跃 | 90天 | 各策略胜率统计、活跃市场规律、历史高价值交易复盘 | `memory/trade_patterns.jsonl` |
| **P2** | 短期上下文 | 30天 | 今日各品种K线结构状态、近期信号质量、当前持仓背景 | `memory/market_state.json` |

## 5. K 线摘要 API 设计

### 5.1 问题

当前如果直接传原始 K 线给 Agent：
- 200 根 5m K 线 ≈ 3,000+ token
- 6 个品种 = 18,000 token/次分析
- 每天 96 次 = 每日消耗 1,728,000 token（约 $5/天）

### 5.2 解决方案：后端预处理

在 data-service 新增 `/api/kline-summary/{symbol}` 接口，返回结构化摘要：

### 5.3 实现位置

文件：`AB Console-Backend/services/data-service/src/routers/kline_summary.py`（新增）

逻辑：

2. 计算 ATR(14)、EMA20/50/200、斜率
3. 判断区间/趋势状态（简单规则，不用 LLM）
4. 识别关键支撑阻力位（近期摆动高低点）
5. 描述最近 5 根 K 线的行为
6. 返回结构化 JSON

## 7. Agent 角色重设计

### 7.1 新的 SKILL.md 结构（al-brooks）

V5.0 SKILL.md 框架（替换现有版本）：

```markdown
# 🦁 AL Brooks PA 交易助手 — 行动手册 V5.0

## 身份
你是一个经过 Al Brooks《价格行为交易》完整课程训练的交易分析师。
你的分析基于 Al Brooks 方法论，不依赖传统技术指标。

## 分析流程（每次收到信号或触发分析时执行）

### 步骤 1：获取当前上下文
1. 读 ~/.openclaw/workspaces/trading-shared/.abstract（了解有什么）
2. 读 ~/.openclaw/workspaces/trading-shared/memory/market_state.json（当前结构）
3. 读 ~/.openclaw/workspaces/trading-shared/MEMORY.md（决策框架）

### 步骤 2：调用 K 线摘要 API
curl http://localhost:8088/api/kline-summary/{symbol}
（不直接请求原始 K 线）

### 步骤 3：Al Brooks 四步分析
1. 判断市场状态（急速/趋势通道/震荡区间？）
2. 选择对应策略（参考 DECISION_FRAMEWORK.md 的策略矩阵）
3. 检查入场条件（是否满足所有前提？）
4. 评估风险（盈亏比是否 ≥ 2:1？今日是否已止损 2 次？）

### 步骤 4：决策
- 满足所有条件 → 执行入场
- 不满足 → 记录原因，等待下次机会
- 市场状态不明确 → 观望

### 步骤 5：更新记忆
- 无论是否入场，更新 market_state.json 的 last_analysis 字段
- 入场后更新 SESSION-STATE.md

## 信号的处理方式
TradeCat 信号 = 提醒你关注某个品种，不是交易指令
收到信号后：先做步骤 1-4 的独立分析，再决定是否采取行动
如果信号方向与 Al Brooks 分析矛盾 → 以 Al Brooks 分析为准
```

### 7.2 新的触发机制


## 11. 附录：关键参考资料

### Al Brooks 核心原则（不可违背）

1. **80/20 规则**：趋势中 80% 反转尝试失败；区间中 80% 突破尝试失败
2. **Always In**：市场任何时刻都偏向多头或空头，永远不是真正的"中性"
3. **第二次入场**：第一次突破常失败，等待回调确认（H2/L2）
4. **止损要合理**：太紧止损只会被洗出；止损 = ATR × 2.0 是合理基线
5. **盈亏比优先**：低于 2:1 盈亏比的交易不做，宁可错过

- 信号历史表：`signal_events`（TimescaleDB）
- 价格历史表：`klines_5m`（TimescaleDB）
- 评估周期：信号后 15m、1h、4h 的价格变动方向
