# V5.0 ab_* 模块集成方案

## 📋 概述

本文档详细说明如何将 ab_sr/ab_mm/ab_patterns 三个 Al Brooks 价格行为分析模块集成到 patrol-l1 (V4.3) 中，升级为 V5.0。

**核心原则**：
- ✅ 新模块 = 计算层（提供精确数值）
- ✅ S 文件 = 决策层（教 agent "怎么想"）
- ✅ 两层架构：数值层 + 决策层 = 完美融合
- ✅ 知识体系不变：S 文件的引用关系和思考流程完全保留

---

## 🎯 集成目标

### 解决的问题
1. **Premise Check 形式化**（⚠️ 不完整）
   - 当前：只写"5项✓"，没有具体内容
   - 优化后：每项都有数值支撑（支撑 2050.5 (swing_low)，距离 0.45%）

2. **BNB 最优入场点被错过**（✗）
   - 当前：Quick Scan 纯数值检测 → Phase B 读 S 文件（2 分钟）→ 最优点已过
   - 优化后：Quick Scan 预计算 R（≤ 1 秒）→ R ≥ 1.5:1 → 立刻进 Phase B

3. **周期不全**（⚠️）
   - 当前：15m、1h 的 setup 扫描被压缩
   - 优化后：3 品种 × 3 周期 = 9 次预计算（≤ 10 秒）

4. **速度优化**
   - 当前：每个品种 Phase B 分析 ~2 分钟
   - 优化后：Quick Scan ≤ 1 秒/品种，Phase B 仍然 ~1 分钟（但只处理有信号的品种）

## 📊 当前逻辑（V4.3）

### 完整流程

```
Step 0: 加载缓存 (market_state_l1.json)
  ↓
Step 1: 全局数据获取
  - 获取 3 品种 × 3 周期 K 线
  - 获取 Daily 数据（检查缓存 expires_at）
  ↓
Step 2: 持仓管理（有持仓时）
  - Read S2/S3/S3b/S7
  - Premise Check（5 项检查）
  - 决策：继续持有 / 平仓 / 移 SL
  ↓
Step 3 Phase A: Quick Scan（全 5 品种）
  - 纯数值检测（不读 S 文件）
  - 6 类事件：anomaly/level_break/tr_edge/momentum/ema_touch/h2_l2_trigger
  - 无事件 → 跳过
  - 有事件 → 进入 Phase B
  ↓
Step 3 Phase B: 深分析（仅有事件品种）
  - 按事件类型加载 1-2 个 S 文件
  - 结合 K 线数据 + S 文件知识
  - 决策：入场 / PASS
  ↓
Step 4: 输出 + 写回缓存
  ↓
Step 5: 定时器（智能间隔 2-12 分钟）
```

### 关键特性（V4.3）
- **缓存驱动**：market_state_l1.json 持久化缓存
- **两阶段扫描**：Phase A Quick Scan → Phase B Deep
- **6 项执行强化**：路由表自检、PASS 分类、SL 重入、Scalp 快速通道等
- **智能定时器**：P0-P5 优先级，2-12 分钟动态间隔
- **Discord 推送**：开仓/平仓/移 SL/周期汇报

## 🚀 集成后逻辑（V5.0）

### 完整流程

```
Step 0: 加载缓存 (market_state_l1.json)
  ↓
Step 1: 全局数据获取
  - 获取 3 品种 × 3 周期 K 线
  - 获取 Daily 数据（检查缓存 expires_at）
  ↓
Step 2: 持仓管理（有持仓时）
  ┌─────────────────────────────────────┐
  │ 🆕 调用新模块（计算层）              │
  │ - sr_info = analyze_ab_sr(klines)   │
  │ - pat_info = analyze_ab_patterns()  │
  └─────────────────────────────────────┘
  - Read S2/S3/S3b/S7（决策层）
  - Premise Check（5 项检查，结合新模块数值）
    a. AI 方向: {S2 分析} vs 持仓方向
    b. 市场状态: {pat_info.pressure.direction} = bull_pressure
    c. 入场前提: {sr_info.nearest_support} = 2050.5 (swing_low)
    d. 浮盈状态: +1.2%
    e. 强反向 BO: {pat_info.latest_l} = None
  - 决策：继续持有 / 平仓 / 移 SL
  ↓
Step 3 Phase A: Quick Scan（全 3 品种 × 3 周期）
  ┌─────────────────────────────────────┐
  │ 🆕 按需调用新模块（计算层）          │
  │ - 纯数值检测（6 类事件）            │
  │ - 有事件 → 按需调用：               │
  │   - level_break/tr_edge → ab_sr    │
  │   - h2_l2_trigger → ab_sr + ab_mm  │
  │   - anomaly → ab_patterns          │
  └─────────────────────────────────────┘
  - 无事件 → 跳过
  - 有事件 + R ≥ 1.5:1 → 进入 Phase B
  ↓
Step 3 Phase B: 深分析（仅有事件品种）
  - 使用 Quick Scan 预计算的数值（sr_info/mm_info/pat_info）
  - Read S 文件（决策层）
  - 结合数值 + S 文件知识
  - 决策：入场 / PASS
  ↓
Step 4: 输出 + 写回缓存
  ↓
Step 5: 定时器（智能间隔 2-12 分钟）
```

### 新增特性（V5.0）
- **计算层**：ab_sr/ab_mm/ab_patterns 预计算数值
- **按需调用**：只在有事件时调用，无事件时不调用
- **时间戳**：每个模块返回 computed_at 和 data_timestamp
- **速度优化**：Quick Scan ≤ 1 秒/品种（vs 原来的 2 分钟）
- **精准度提升**：Premise Check 每项都有数值支撑

## ⚠️ 风险与缓解

### 风险 1：过度依赖数值
**风险**：agent 可能过度依赖预计算的数值，忽略 S 文件的"思考过程"

**缓解**：
- ✅ 新模块只用于 Quick Scan 和 Premise Check
- ✅ Phase B 深分析仍然要 Read S 文件
- ✅ S 文件的引用关系不变（S0→S1→S2→S3→S3b→S4→S5→S6→S7）

---

### 风险 2：缓存过期
**风险**：market_state_l1.json 缓存过期，导致数据不准确

**缓解**：
- ✅ 方案 2（推荐）：新模块数据每轮重新计算（≤ 15 秒）
- ✅ 加时间戳：computed_at 和 data_timestamp
- ✅ 缓存只用于 Phase B 深分析，Quick Scan 每轮重新计算

---

### 风险 3：计算开销
**风险**：3 品种 × 3 周期 × 3 模块 = 27 次调用，可能影响速度

**缓解**：
- ✅ 优化 1（按需调用）：只在有事件时调用，无事件时不调用（~10 次/轮）
- ✅ 优化 2（缓存 K 线）：避免重复获取 K 线数据
- ✅ 优化 3（并行调用）：并行处理多个信号（≤ 2 秒）
