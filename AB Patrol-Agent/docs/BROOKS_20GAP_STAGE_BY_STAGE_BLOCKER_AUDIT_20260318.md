# 20-gap 模板逐环节阻塞审计

更新日期：2026-03-18

## 1. 目标

这份文档只回答一个问题：

`20均线缺口` 当前为什么还没有稳定盈利，主阻塞到底卡在模板的哪一环。

本轮不再泛泛讨论，而是按模板链路逐项检查：

1. 背景
2. setup
3. signal bar
4. STOP 入场
5. 初始止损
6. actual risk
7. 第一目标
8. rescue / close-test / swing 分层
9. 持仓管理
10. 提前离场
11. 成本覆盖
12. 宽样本结果

## 3. 交易员语境下，20-gap 本来应该是什么

按 Brooks / 太妃语境，`20-gap` 不是 generic scalp。

它更像：

- 趋势长期在 EMA 同侧
- 舒适区大致 `20-30` 根
- 第一次回到 EMA 附近
- 出现同侧恢复 signal
- 先看测试原趋势极值
- 弱背景里才降成 `close-test / scalp`

所以它天然有两层：

- `trend recovery continuation`
- `test / scalp`

当前系统真正的问题，不是没做后半段，而是这两层虽然都做了，但弱背景单的质量还没分干净。

## 4. 逐环节检查

### 4.1 背景

当前已经统一了：

- `结构周期 / 主背景周期 / 锚定周期`

这个大问题现在不是 `20-gap` 的主矛盾。

证据：

- 修一个 `valid_previous_entry` 链路 bug，就能明显改善 `5m`
- 说明现在不是“5m 背景错、15m 背景对”
- 当前主要差异来自 setup/管理，不是多周期框架本身

结论：

- `背景层：基本可用，不是当前第一阻塞`

### 4.2 setup

这是当前第一阻塞。

目前 `20-gap` 最大的问题不是没候选，而是：

- detector 过早把很多单压成 `test`
- 或者虽然进了 `continuation`，但在 `broad_range` 里其实没有新鲜回踩、没有收复、没有恢复腿

也就是说：

- `setup 分桶` 还没有完全贴住 Brooks 语义

结论：

- `setup：主阻塞`

### 4.3 signal bar

当前坏单里，大多数不是奇怪的 `reversal_bar`，而是正常 `trend_bar`。

这说明：

- `signal bar` 不是当前最主要问题
- 简单砍掉 `reversal_bar` 不会解决 20-gap

结论：

- `signal bar：次要阻塞`

这轮新增的更细结论是：

- `v34` 的 `F1 / R1 / P1` 里，`broad_range + scalp-only` 这簇几乎清一色都是 `trend_bar`
- `signal_bar_tail_ratio / close_position / quality` 在三组样本里没有形成稳定统一的全局切分线
- 所以“再加一条弱棒阈值”不是当前最可能的突破口

### 4.4 STOP 入场

当前 `20-gap` 已按模板走：

- signal bar
- 外一跳 `STOP`
- 真触发才成交

这一步没有发现是当前主问题。

结论：

- `STOP 入场：基本对齐`

### 4.5 初始止损

当前 broad range 弱单里仍然有很多直接走到 `SL`。

这说明两种可能：

1. 入场质量不够
2. 止损对这簇仍偏“结构过宽”

但从目前数据看，更多像第一种。

因为：

- 已经把这簇降成 `scalp-only`
- 仍然很多单在出现足够利润前就直接打止损

这更像“单子本身就不该做”，不是单纯“止损太远”。

结论：

- `初始止损：有影响，但不是第一阻塞`

### 4.6 actual risk

这条链已经打通。

当前没有证据表明：

- `actual risk`
- 或成本覆盖门槛

本身有口径错误。

结论：

- `actual risk：不是当前阻塞`

### 4.7 第一目标

当前代码里，目标位并不是“必须前高/前低”。

实际上是分层的：

- `continuation`
  - 优先 `trend_extreme_target`
  - 顺序是：
    - `prior high / prior low`
    - `highest close / lowest close`
    - `pullback origin / 2x`
- `test`
  - 优先 `close_test_target`
  - 其次 `rescue_target`
  - 再其次 `swing_target`

所以问题不是：

- “系统死板要求必须打到前高/前低”

而是：

- 这些单很多还没来得及走到任何合理目标，就先打 `SL`

换句话说：

- `目标位略收一点` 可能有边际帮助
- 但它不是当前主阻塞

结论：

- `目标位：不是第一阻塞`

补充说明：

- `P1` 的亏损单里，确实有一部分曾给过 `0.2R~0.5R` 的正向 excursion
- 这说明目标略收近不是完全没用
- 但统一收近只会救一部分 `5m` 压力样本，同时打坏 `F1 / R1`
- 所以目标只能按子簇细分，不能全局统一收

### 4.8 rescue / close-test / swing 分层

这是当前第二阻塞。

本轮最重要的进展就是确认：

- `broad_range + close-test`
  这簇不该默认当 `brooks_tr_blshs / swing`
- 把它改成 `scalp-only` 后
  - `F1` 变好
  - `R1` 变好
  - `P1` 也从更差位置拉回一点

但还没收官，因为：

- `P1` 里这簇虽然全部降成了 `scalp`
- 仍然是 `10` 笔里 `6` 亏 `4` 赢

结论：

- `预期分层：当前关键进展点，但还没完成`

### 4.9 持仓管理

后半段不是没做。

当前已经有：

- scalp
- close-test
- rescue
- swing
- BE
- partial
- runner 开关

但现阶段数据告诉我们：

- 当单子能动起来时，`scalp` 管理是有效的
- `P1 v30`
  - `SCALP` 出场：`7` 笔，`6` 赢 `1` 亏，PF 很高
- 真正的问题是：
  - 很多坏单根本走不到能安全 scalp 出场的阶段
  - 直接先去 `SL`

所以：

- `持仓管理不是没做`
- `也不是当前第一阻塞`

结论：

- `持仓管理：有用，但救不了坏 entry`

### 4.10 提前离场

当前这条 broad range 弱簇，已经开始被提前降成 `scalp-only`。

这一步是正向的。

但仍不够，因为：

- 很多单压根没有给出足够利润进度
- 所以还来不及触发更好的保护退出

结论：

- `提前离场：方向对，但不是根因`

### 4.11 成本覆盖

当前 entry block 里仍有大量：

- `gap 第一目标仅 xR，低于覆盖成本所需的 yR`

这一步应该保留。

因为它拦的是“连成本都覆盖不了”的坏单，不是主盈利拖累。

结论：

- `成本覆盖：必要过滤，不是当前主阻塞`

## 5. 当前真正卡住的地方

到这一步，可以明确排除几个常见误判：

- 不是背景框架又错了
- 不是 signal bar 类型错了
- 不是必须把目标改得更近就能盈利
- 不是后半段管理根本没做

当前真正卡住的是：

`broad_range` 里的弱恢复 `20-gap`，哪一些其实连 scalp 都不该做。

更直白一点：

- 现在系统已经能把一大部分坏单从 `swing` 降到 `scalp`
- 这一步对 `F1 / R1` 是有效的
- 但 `P1` 还说明：
  - 其中仍有一批单，即使按 `scalp-only` 处理，也会先去 `SL`

所以下一刀不能再去动：

- 大背景
- 通用目标位
- 通用持仓管理

下一刀应该继续只查：

- 当前是不是“干净基线 + 单一新改动”
- `broad_range + scalp-only` 里哪些单几乎不给 `MFE`
- 哪些单给过 `0.2R~0.5R` 但没吃到
- 哪些单其实一开始就不该用 `STOP`

- 这批 `broad_range + scalp-only` 单子
- 哪些在进场后几乎没有正向波动
- 哪些其实是错误半区、坏尾巴、或信号后没有任何 follow-through

---

## 6. 关于“目标位是不是太远”

这是这轮最容易误判的点。

答案是：

`目标位不是当前第一阻塞。`

原因：

1. 当前代码本身并不死板要求必须到前高/前低。
2. 很多坏单已经降成 `scalp-only`，并不是还在等远目标。
3. `P1 v30` 里 broad range 这簇已经全部是 `scalp`，仍然有一半以上亏损。

所以现在如果先去“把目标再收一点”，大概率只是：

- 改善一部分已经能动起来的单
- 但救不了那些进场后直接向反方向走的单

也就是说：

- 目标位还能优化
- 但它不是当前最值的一刀

---

## 7. 当前最值的下一步

不再发散，继续只打：

- `broad_range + scalp-only` 这簇

顺序：

1. 给逐笔审计补 `MFE / MAE / 最佳R / 最差R`
2. 看这簇里亏损单在打止损前，是否连 `0.2R ~ 0.3R` 的正向波动都没有
3. 如果没有，就说明问题是 `entry/setup`
4. 如果有，但还是没吃到，就说明问题是 `protective / scalp 退出参数`

这一步做完，才能决定：

- 下一刀是收 `entry`
- 还是收 `scalp` 出场

---

## 8. 结论

当前 `20-gap` 还远没到稳定盈利，更没到 `PF >= 2`。

但目前不是完全没进展。

已经明确打通的有：

- 多周期角色统一
- 背景周期计数
- `valid_previous_entry`
- 模板目标不再被通用路由覆盖
- `broad_range` 弱簇不再默认按 `swing`

当前最核心的卡点已经很具体：

`broad_range` 里的弱恢复单，仍有一批即使按 `scalp-only` 处理，也会先去 `SL`。`

这说明：

- 问题已经不是大框架
- 而是最后一层弱 entry 质量

后面继续优化，也必须围绕这一簇做，而不是再回到泛泛的 detector 或背景参数。
