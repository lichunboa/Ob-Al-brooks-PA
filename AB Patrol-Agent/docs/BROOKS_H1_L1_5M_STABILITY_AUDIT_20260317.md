# H1/L1 5m 稳定性补充审查

更新时间：2026-03-17

## 一、为什么补这轮 5m 审查

用户提出了一个关键问题：

- Al Brooks 主要做 `5m` 纳指；
- 如果我们现在的 `H1/L1` 在 `15m` 表现更稳定、`5m` 更容易出问题，
- 就必须确认这是不是：
  - 对 `15m` 的隐性特调；
  - 对 Brooks 理解还不够；
  - 或者 `5m` 只是把系统里原本就存在的弱点放大了。

本轮补充审查的目标，就是只看 `H1/L1` 单策略，在更多 `5m` 品种/窗口里验证当前模块的稳定性。

## 三、这组 5m 数据说明什么

最重要的结论不是“5m 全都不行”，而是：

1. `5m` 不是统一坏。  
   `BNB 5m` 已经是正 PF，说明当前模块不是天然不适合 `5m`。

2. `5m` 是更严格的验收场。  
   同样是 `H1/L1`，在 `BTC 5m` 和 `ETH 5m` 上，弱背景、弱 follow-through、目标过近、成本磨损会更快暴露出来。

3. 当前剩余问题集中在“弱 `H1/L1` 的处置边界”，不是 `STOP trigger`。  
   `STOP trigger` 现在已经对了；真正不稳的是：
   - 弱 `signal bar`
   - `fade_candidate` 的触发与执行
   - `first-entry` 在弱背景里的保本/小利退出

## 四、ETH 5m 为什么这么差

`ETHUSDT 5m 2024Q3` 的逐笔拆单结果显示：

- 总交易 `14`
- 胜率 `14.29%`
- PF `0.171`

结构特征：

- `11/14` 是 `低1`
- `10/14` 被分流成 `scalp_only`
- `0/14` 真正执行成 `fade`
- `13/14` 的管理风格仍然落在 `brooks_tr_blshs`
- 退出主要是：
  - `SL = 8`
  - `SCALP = 2`
  - `TP = 4`

这说明：

- 当前系统已经能识别“这是弱 `H1/L1`”
- 但很多单只被降成了 `scalp_only`
- 还没有真正变成 Brooks 语义里的 `fade weak signal / no trade / BE rescue`

也就是说，当前 `5m` 的主问题不是 detector 完全不对，而是：

- 弱 `H1/L1` 的后续处置仍然不够凶
- 在 `ETH 5m` 这种弱背景里，很多单本来就不该继续顺势拿

## 五、本轮尝试过但没有保留的优化

我试过两刀：

1. 把 `scalp_only` 强制改成 `brooks_scalp`
2. 放宽 `fade_candidate` 触发范围

结果：

- 第一刀对固定回归基本中性，对最差样本也没有改善
- 第二刀在 `ETH 5m` 上是负优化，PF 从 `0.171` 掉到 `0.117`

所以这两刀都没有保留进当前代码基线。

## 六、当前最稳的结论

到这一步，可以比较明确地说：

1. `H1/L1` 的 `STOP trigger` 是对的，不能回退。
2. 弱 setup 分流这个方向是对的，不能回退。
3. `5m` 的问题不是“换一套周期理论”，而是：
   - 弱背景更多
   - 目标更近
   - 成本磨损更敏感
   - 所以更容易暴露 `fade / no-trade / rescue` 这层还没完全对齐 Brooks

## 七、下一步建议

在继续扩到 `H2/L2`、突破回调和 gap 族之前，建议先把 `H1/L1` 的剩余问题再打透一层：

1. 继续拆 `ETH 5m 2024Q3`  
   重点不是“再放宽 signal”，而是确认哪些弱 `L1/H1` 该：
   - `no trade`
   - `fade`
   - `BE rescue`

2. 继续核对 Ali Flash Cards 和百科里的弱一信号案例  
   尤其是：
   - `Fade Weak L1`
   - `Disappointed Bulls / Bears`
   - `lower buy / higher sell`

3. 只有当 `BTC/ETH 5m` 也站稳以后，再把当前模块扩到：
   - `H2/L2`
   - 突破回调
   - `20均线缺口 / 第一均线缺口 / MAG`
