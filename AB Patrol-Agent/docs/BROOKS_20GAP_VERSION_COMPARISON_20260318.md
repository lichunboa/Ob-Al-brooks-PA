# 20-gap 关键版本对照表

更新日期：2026-03-18

## 1. 文档目的

这份文档只做一件事：

把 `20-gap` 这轮优化过程中真正关键的版本、对应改动、以及回测后的变化拉成一张对照表。

目的不是复述所有实验，而是回答：

1. 哪些改动是真正有效的；
2. 哪些改动只是单场景好看；
3. 当前为什么还没有稳定到 `PF >= 2`；
4. 后面继续归零时，应该优先沿哪条线继续。

## 3. 每一步到底改了什么

### 3.1 `v1 -> v12`

这一步是真突破，不是小修小补。

主要修复：

1. `bars_away` 从执行周期计数，改成背景周期计数；
2. `valid_previous_entry` 不再被通用链覆盖；
3. `20-gap` 模板目标不再被通用路由目标覆盖；
4. gap 审计链补齐。

理论依据：

- Brooks `5m` 图挂 `60m EMA` 的语义，不是按 `5m bars away` 在数；
- `20-gap` 本身有自己的目标层级，不能被通用目标重写。

结果：

- 家族级 `fixed / stress5m` 都明显改善；
- 这一步是当前 `20-gap` 能走通的基础。

### 3.2 `v12 -> v23`

这一步的价值在于把“同名不同物”的 bug 继续收掉。

主要修复：

1. detector 写入的 gap 目标层级优先保留；
2. `valid_previous_entry` 透传修好；
3. `test / continuation` 的目标与管理不再被完全冲掉。

结果：

- `F1 / R1` 都能转正；
- 但 `P1` 仍明显不过线。

结论：

- `20-gap` 不是彻底不行；
- 当前真正难的是弱 `5m` 压力样本。

### 3.3 `v23 -> v34`

这一步是目前第二个真实有效的提升。

主要改动：

- 对 `broad_range + close-test + scalp-only` 这簇，加入更窄的 `no_trade` 拦截：
  - `reversal_bar` 不做
  - 或者 `trend_bar` 但尾巴偏差、收盘位置差、结构方向不匹配

理论依据：

- Brooks / 太妃都不支持在区间里的弱恢复棒上继续追 weak continuation；
- 弱 close-test 信号棒，本来就应该优先归入 no-trade / 弱 scalp。

结果：

- `F1`: `1.0093 -> 1.0673`
- `R1`: `1.0742 -> 1.1848`
- `P1`: `0.7535 -> 1.0920`

结论：

- 这是目前第一次出现三组核心样本一起正向的阶段。

### 3.4 `v35`

这一步证明了一个重要事实：

- 弱 `broad_range test` 的入场方式，确实是值得怀疑的；
- 但“统一改成 limit”不是通用解。

主要实验：

- 把 `broad_range + ema_gap_test + close-test` 的入场，从统一 `STOP` 追价，试着改成 `LIMIT`

结果：

- `F1` 单独改善到 `1.3259`
- `R1` 直接掉到 `0.6849`

结论：

- 这说明“追价方式”确实可能是 blocker；
- 但它不能用一条全局规则直接改。

### 3.5 `v36`

这一步证明另一个常见误区：

- “再加一个看起来合理的弱 bar 过滤”不一定有用。

实验：

- 在弱棒规则里追加“极端收盘 + 尾巴”的 trend bar 过滤

结果：

- `F1` 从 `1.0673` 掉到 `1.0391`

结论：

- 这条规则证伪，已回退。

### 3.6 `v37`

这一步是当前最值得继续验证的新方向。

主要改动：

- 只把**非 `5m`** 的：
  - `signal_type = 20均线缺口`
  - `market_state = broad_range`
  - `management_template = ema_gap_test`
  - `first_target_is_close_test = True`
- 从 `STOP` 追价，改成更贴近区间回踩语义的 `LIMIT`

关键点：

- `5m` 不动，继续沿用原本的 `TR_LEG_RECOVERY` limit 路由逻辑；
- 也就是说，这不是“全周期统一改 limit”，而是只补 `15m/1h` 这类之前没有走 limit 语义的弱 test。

结果：

- `F1` 直接回到 `v35` 那个更优值：
  - 交易 `9`
  - 日频 `0.2903`
  - 胜率 `55.56%`
  - PF `1.3259`
- 新审计已能直接看到：
  - `broad_range + ema_gap_test` 的成交单，确实是 `LIMIT`

当前判断：

- 这一步不像 `v35` 那样会一并破坏 `5m`；
- 它更像在修一个“非 5m 弱 close-test 仍在追 stop”的链路缺口；
- 但 `R1 v37` 又异常掉到 `0.5781`，这说明当前工作区里还混着别的未收口实验；
- 所以后面第一件事不是直接提交，而是先把版本隔离干净，再重新验证。

### 3.7 `v38`

这一步不是新策略优化，而是把 `runner.py` 里混入的 `v37` 单实验重新拆掉，并把基线重新跑平。

同时还补了一条不改策略语义的工程修复：

- [market_replay.py](/Users/mitchellcb/Desktop/Obsidian/Al-brooks-PA/AB Patrol-Agent/libs/backtest/market_replay.py)
  增加按 `virtual_time` 失效的 `get_candles()` 轻量缓存

目的只有两个：

1. 恢复“干净基线 + 单一新改动”的验证状态；
2. 让 `fixed / random / stress5m` 能稳定跑完，不再被窗口切片性能拖死。

结果：

- `fixed` 回到 `v34`：
  - 交易 `20`
  - 日频 `0.2151`
  - 胜率 `50.00%`
  - PF `0.7507`
- `random` 回到 `v34`：
  - 交易 `9`
  - 日频 `0.0726`
  - 胜率 `55.56%`
  - PF `0.2962`
- `stress5m` 完整重跑：
  - 交易 `71`
  - 日频 `0.3272`
  - 胜率 `57.75%`
  - PF `1.6348`

结论：

- 现在可以确认，`v37` 的异常不是“20-gap 突然又坏了”，而是基线里混进了单实验残留；
- 当前可信的基线应回到 `v38`；
- 下一刀必须建立在这个干净基线上，而不是继续拿混合状态解释结果。

## 4. 当前最可能的主阻塞

从版本对照看，当前真正的主阻塞已经缩成下面两层，不再是“大而化之的背景问题”。

### 4.1 弱 `broad_range + close-test` 的入场质量

已经确认：

- 目标位过远不是唯一 blocker；
- 后半段管理不是空白；
- detector 也不是完全没放出频率；
- 真正困难的是这簇弱单里，哪些本来就几乎不给正向 excursion。

也就是说：

- 这里更像 `entry quality` 问题；
- 不是纯粹的 `target` 问题。

### 4.2 `STOP` / `LIMIT` 语义在弱区间里的细分

`v35` 已经证明：

- 入场方式很可能是重要问题；
- 但不能一刀切把所有弱 `20-gap test` 都改成 `LIMIT`。

当前更合理的判断是：

- 区间里的弱 `close-test`
- 需要更细的“哪些该 limit，哪些仍可 stop”的子分桶
- `v37` 已经把这个问题收紧到：
  - **非 5m** 弱 close-test 可以优先试 `LIMIT`
  - `5m` 则继续保留现有链路，避免再次打坏 `R1`

---

## 5. 当前不该再重复的路

后面继续优化 `20-gap` 时，不要再重复下面这些已证伪路线：

1. 继续盲放宽 detector continuation
2. 统一收近所有弱 scalp 目标
3. 统一把 broad range test 改成 limit
4. 再加一条看似合理的弱 bar 阈值，希望直接救全局

这些都只会带来单窗口改善，不能稳定跨样本。

---

## 6. 后面该继续怎么打

基于当前对照表，后面继续优化 `20-gap` 的顺序应该是：

1. 固定 `v34` 作为当前更稳的可参考工作基线；
2. 每轮正式验证前，先确认当前代码是“干净基线 + 单一新改动”；
3. 在 `broad_range + close-test + scalp-only` 这簇里继续查：
   - 哪些亏损单几乎没有 `MFE`
   - 哪些亏损单有 `0.2R~0.5R` 但没吃到
4. 把“入场质量问题”和“退出参数问题”彻底拆开；
5. 再决定下一刀是：
   - 细分 `LIMIT / STOP`
   - 还是继续只打弱簇里的 `entry quality`

一句话总结：

`20-gap` 现在不是没方向，而是已经进入“最后真正有价值的细分层”。下一步必须继续沿着坏簇和逐笔 excursion 走，不能回头再做泛化参数调优。
