# Knowledge Index (2026-03-09)

这份索引回答 4 个问题：

1. 当前 Patrol 知识分成哪几层
2. 每层负责什么，不负责什么
3. 修改某类问题时，应该先改哪一层
4. `S0-S7` 与 `C/Q/运行说明` 当前如何协作

---

## 一、四层结构

| 层 | 作用 | 典型内容 | 不应放入 |
|---|---|---|---|
| `SKILL` | 流程编排、阶段切换、Step 0-5 路由 | 何时快扫、何时深分析、何时管理仓位 | API、命令、端口、消息模板、理论长解释 |
| `S0-S7` | 可执行交易规则与 playbook | 状态判定、关键位、策略匹配、评估、入场、管理 | 课程背景、原话摘录、运行维护 |
| `C0-C5` | Al Brooks 理论规范层 | 市场周期、触发分类、风格/方程、管理原则、Step 5 | 直接下单动作、接口细节 |
| `Q1-Q6` | 纪律纠偏与原话锚点 | 方向纪律、恐惧纠偏、TE 原话、管理纪律 | 新交易规则、阈值、执行语义 |

## 二、运行时如何读

运行时不是每轮去 Obsidian 全库查资料，而是按状态路由：

1. 读取 `SKILL` 的流程章节
2. 读取对应 `S0-S7` 的可执行规则
3. 必要时补 `C` 里的理论边界
4. 必要时补 `Q` 里的纪律纠偏

因此：

- `Obsidian Al Brooks 知识库` = 最高权威与维护来源
- `C/S/Q/SKILL` = 运行时实际注入主链

---

## 三、怎么维护

### 如果问题是“理论说法不对”

先改：

1. Obsidian 知识库
2. `canonical/C*.md`
3. 再回写相关 `S`

### 如果问题是“setup 规则不对”

先改：

1. 对应 `S0-S7`
2. 如果需要理论依据，再补 `C`
3. 不要先去改代码阈值

### 如果问题是“agent 太保守/太犹豫/太想完美”

先改：

1. `Q*.md`
2. 必要时改 `S5/S6/S7` 的纪律性句子

### 如果问题是“流程顺序不对”

改：

1. `SKILL.md`
2. 运行时路由

### 如果问题是“端口/API/命令/TG/Web/图表/守护进程”

改：

1. 运行说明文档
2. runtime / Web / watchdog / start 脚本

## 四、当前维护顺序

1. 先看 `SKILL` 是否只保留了流程
2. 再看 `S0-S7` 是否只保留可执行规则
3. 再看 `C/Q` 是否把理论与纪律承接好了
4. 最后再看代码有没有偷偷发明新门槛
