## 执行摘要

### 迁移目标
将 Obsidian 插件中的**实时交易功能**（图表、扫描仪、信号）迁移到 Web Dashboard，同时保持 Obsidian 专注于**知识管理**功能。

### 关键里程碑

```
Week 2:  Web 端基础框架 + 后端 WebSocket 可用
Week 4:  K线图表 + 市场扫描仪 双轨运行
Week 6:  信号系统 + 策略回测 双轨运行
Week 8:  数据同步完成，两端数据一致
Week 10: Obsidian 开始减负（删除重型组件）
Week 12: 完整迁移完成，Obsidian 精简版发布
```

### 成功标准

1. **功能完整性**: Web 端 100% 覆盖 Obsidian 端所有交易功能
2. **用户体验**: Web 端图表流畅度 > Obsidian 端（60fps vs 卡顿）
3. **数据无损**: 所有历史数据、配置、笔记完整保留
4. **平滑过渡**: 用户可以自由选择使用哪一端，无强制迁移

#### API 契约

```typescript
// WebSocket 事件定义 (共享类型文件)
interface WSEvents {
  // 客户端 → 服务端
  'sub:candles': { symbol: string; interval: string };
  'unsub:candles': { symbol: string; interval: string };
  'sub:signals': { symbols?: string[] };
  'unsub:signals': {};
  'ping': { timestamp: number };
  
  // 服务端 → 客户端
  'candle:update': {
    symbol: string;
    interval: string;
    candle: Candle;
  };
  'signal:new': Signal;
  'pong': { timestamp: number; latency: number };
  'error': { code: string; message: string };
}
```

### 4.3 冲突解决策略

```typescript
// 乐观锁机制
interface SyncRecord {
  id: string;
  data: any;
  version: number;      // 版本号，每次更新 +1
  modifiedAt: number;   // 时间戳
  modifiedBy: 'obsidian' | 'web';
}

// 冲突检测
if (local.version < remote.version) {
  // 远程版本更新，使用远程
  applyRemote();
} else if (local.version === remote.version && local.data !== remote.data) {
  // 版本相同但内容不同，需要合并
  showConflictResolver();
}
```

## 风险管控

### 风险矩阵

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| WebSocket 不稳定 | 中 | 高 | 降级到 HTTP 轮询，自动重连 |
| 数据同步冲突 | 低 | 高 | 乐观锁 + 冲突检测 + 手动解决 |
| 用户抵触迁移 | 高 | 中 | 保留 Obsidian 功能直到自愿迁移 |
| 开发延期 | 中 | 中 | 模块化开发，可独立交付 |
| 浏览器兼容性 | 低 | 中 | 提供浏览器检测，不支持时回退到 Obsidian |
