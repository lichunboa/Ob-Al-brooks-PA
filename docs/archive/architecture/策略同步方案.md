# 策略同步方案

> 解决 Obsidian 和 Web Dashboard 策略逻辑同步问题

## 问题

- Obsidian 用 TypeScript 在本地计算策略（`useStrategyMarkers.ts`）
- Web Dashboard 也需要同样的策略逻辑
- 修改策略时需要改两处，容易不一致

## 解决方案：后端集中计算

```
┌─────────────────────────────────────────────────────────┐
│                    策略数据源                             │
│              （K线、指标、市场状态）                        │
└─────────────────────────┬───────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────┐
│              后端策略引擎 (Python)                        │
│                                                         │
│   ┌─────────────────────────────────────────────────┐   │
│   │  策略规则库 (src/strategies/rules.py)            │   │
│   │  - h1_breakout: H1高点突破                        │   │
│   │  - l1_breakout: L1低点突破                        │   │
│   │  - ema20_gap: EMA20缺口                           │   │
│   │  - bollinger_bounce: 布林带反弹                    │   │
│   │  - trend_strength: 趋势强度                        │   │
│   │  - volume_spike: 成交量突增                        │   │
│   └─────────────────────────────────────────────────┘   │
│                                                         │
│   ┌─────────────────────────────────────────────────┐   │
│   │  策略引擎 (src/strategies/engine.py)             │   │
│   │  - 计算技术指标（EMA、布林带等）                    │   │
│   │  - 运行策略规则                                   │   │
│   │  - 输出信号结果                                   │   │
│   └─────────────────────────────────────────────────┘   │
└─────────────────────────┬───────────────────────────────┘
                          ▼
        ┌─────────────────┴─────────────────┐
        │                                   │
        ▼                                   ▼
┌───────────────┐                  ┌───────────────┐
│  Web Dashboard │                  │   Obsidian    │
│  (展示信号)    │                  │  (展示信号)   │
│               │                  │               │
│  useStrategy  │                  │  逐步迁移到   │
│  Signals.ts   │                  │  后端计算     │
│  从API获取    │                  │  （可选）     │
└───────────────┘                  └───────────────┘
```

## 优势

| 方面 | 说明 |
|------|------|
| **单一真相源** | 策略逻辑只在一处（Python），修改只需改一处 |
| **计算能力** | Python 更适合数值计算，可用 pandas/numpy |
| **易于扩展** | 新增策略只需后端修改，两端自动生效 |
| **历史回测** | 后端可直接用历史数据进行回测 |
| **AI集成** | 后端可集成机器学习模型进行信号预测 |

## 对比

### 修改前：两端分别计算

```
修改 H1突破策略阈值
    ├── Obsidian: useStrategyMarkers.ts 修改
    ├── Web: useStrategyMarkers.ts (复制) 修改
    └── 测试：需要分别测试两端
    
时间：2x 开发 + 2x 测试
风险：容易遗漏，导致两端不一致
```

### 修改后：后端集中计算

```
修改 H1突破策略阈值
    └── 后端: rules.py 修改
    └── 两端自动生效
    
时间：1x 开发 + 1x 测试
风险：一处修改，全局生效
```

```http

Response:
{
  "symbol": "BTCUSDT",
  "interval": "5m",
  "candles_analyzed": 100,
  "signals": [
    {
      "type": "BUY",
      "name": "H1突破",
      "description": "收盘价突破前高 0.5%",
      "confidence": 75,
      "timestamp": 1706432000,
      "symbol": "BTCUSDT",
      "interval": "5m",
      "metadata": {
        "previous_high": 40000,
        "breakout_strength": 0.5
      }
    }
  ]
}
```

### 获取策略列表

```http
GET /api/v1/strategies

Response:
{
  "strategies": [
    { "id": "h1_breakout", "name": "H1 Breakout", "enabled": true },
    { "id": "l1_breakout", "name": "L1 Breakout", "enabled": true },
    { "id": "ema20_gap", "name": "EMA20 Gap", "enabled": true }
  ]

```

### 配置策略

```http
POST /api/v1/strategies/config
Body: ["h1_breakout", "l1_breakout"]

Response:
{
  "enabled_strategies": ["h1_breakout", "l1_breakout"]
}
```

## Obsidian 迁移路径

### 阶段 1：保持现状（现在）
- Obsidian 继续使用本地 TypeScript 计算
- Web Dashboard 使用后端 API
- 定期手动同步策略逻辑

### 阶段 2：Obsidian 调用后端（可选）
- Obsidian 也改为调用后端 API 获取信号
- 完全统一策略计算逻辑
- 需要网络连接

### 阶段 3：策略配置化（未来）
- 策略规则用 JSON/YAML 定义
- 后端动态加载策略配置
- 用户可自定义策略参数
