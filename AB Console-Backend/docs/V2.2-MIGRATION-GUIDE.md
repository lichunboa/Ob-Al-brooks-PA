# v2.2 架构迁移指南

## 🎯 概述

v2.2 版本引入了全新的基础设施模块，旨在解决以下问题：
1. 硬编码配置
2. 缺乏统一日志
3. 缺乏健康检查
4. 缺乏服务发现
5. 巨型文件难以维护

## 📦 新增模块

### 1. 配置中心 (`libs/common/`)

```
libs/common/
├── __init__.py              # 统一导出
├── service_discovery.py     # 服务发现和配置
├── logging_config.py        # 结构化日志
├── database.py              # 数据库连接池
├── health.py                # 健康检查
├── resilience.py            # 熔断、重试、限流
└── validation.py            # 输入验证
```

### 2. 健康检查端点

| 服务 | 端口 | 端点 |
|------|------|------|
| data-service | 8081 | /health, /health/live, /health/ready |
| signal-service | 8083 | /health, /health/live, /health/ready |

## 🚀 快速开始

### 使用统一配置

```python
# 旧方式（硬编码）
DB_URL = "postgresql://postgres:postgres@localhost:5434/market_data"
API_URL = "http://localhost:8088"

# 新方式（自动适配Docker/本地环境）
from libs.common import get_db_url, get_service_url

db_url = get_db_url()  # 自动检测环境
api_url = get_service_url('api-service')  # http://api-service:8088 或 http://localhost:8088
```

### 使用结构化日志

```python
# 旧方式
import logging
logger = logging.getLogger(__name__)
logger.info(f"数据已加载: {symbol}")

# 新方式
from libs.common import setup_logging

logger = setup_logging(
    service_name='my-service',
    level='INFO',
    enable_file=True,
    structured=True  # JSON格式
)

# 带上下文的日志
logger.info_ctx("数据已加载", symbol="BTCUSDT", records=1000, duration_ms=150)
# 输出: {"timestamp": "2026-02-01T12:00:00Z", "level": "INFO", "message": "数据已加载", "service": "my-service", "symbol": "BTCUSDT", "records": 1000, "duration_ms": 150}
```

### 使用数据库连接池

```python
# 旧方式
import psycopg
conn = psycopg.connect(DB_URL)  # 每次新建连接

# 新方式
from libs.common import init_database, fetch_one

# 启动时初始化
await init_database()

# 使用连接池
result = await fetch_one("SELECT * FROM candles WHERE symbol = %s", ("BTCUSDT",))
```

### 添加健康检查

```python
from libs.common import HealthChecker, create_health_router, check_database
from fastapi import FastAPI

app = FastAPI()

# 创建健康检查器
checker = HealthChecker("my-service", version="2.0.0")

# 注册检查项
checker.register("database", lambda: check_database(get_db_url()))

# 添加路由
app.include_router(create_health_router(checker))

# 现在可以访问:
# GET /health          - 完整健康报告
# GET /health/live     - Kubernetes存活探针
# GET /health/ready    - Kubernetes就绪探针
```

### 使用弹性设计模式

```python
from libs.common import resilient, retry, circuit_breaker

# 自动重试3次，指数退避
@retry(max_attempts=3, base_delay=1.0)
async def fetch_data():
    return await api.get_data()

# 熔断器：连续失败5次后熔断，60秒后尝试恢复
@circuit_breaker(name="binance_api", failure_threshold=5, recovery_timeout=60.0)
async def call_binance():
    return await binance.get_klines()

# 组合：熔断 + 重试
@resilient(
    circuit_name="external_api",
    failure_threshold=5,
    max_attempts=3
)
async def robust_api_call():
    return await external_api.call()
```

### 输入验证

```python
from libs.common import Validator, SymbolValidator, TimeframeValidator

# 定义验证器
validator = Validator(
    symbol=SymbolValidator(),  # 必须是有效的交易对，如 BTCUSDT
    timeframe=TimeframeValidator(),  # 必须是 1m, 5m, 15m, 1h, 4h, 1d
    limit=IntegerField(required=False, min_value=1, max_value=1000)
)

# 验证数据
try:
    data = validator.validate({
        "symbol": "BTCUSDT",
        "timeframe": "5m",
        "limit": 100
    })
except ValidationErrors as e:
    print(e.to_dict())  # [{'error': 'validation_error', 'message': '...', 'field': '...'}]
```

## 🏗️ 架构迁移建议

### Phase 1: 基础设施迁移（本周）

1. **更新所有服务使用统一日志**
   ```python
   # 在每个服务的入口文件
   from libs.common import setup_logging
   logger = setup_logging(service_name='xxx-service')
   ```

2. **添加健康检查端点**
   - 参考 `data-service/src/health_server.py`
   - 参考 `signal-service/src/health.py`

3. **移除硬编码配置**
   ```python
   # 使用环境变量 + 配置中心
   from libs.common import AppConfig
   config = AppConfig()
   bot_token = config.get_bot_token()
   ```

### Phase 2: 代码重构（本月）

#### 拆分巨型 app.py (telegram-service)

建议的目录结构：

```
telegram-service/src/bot/
├── app.py                    # 精简到 <500行，只保留主流程
├── core/
│   ├── __init__.py
│   ├── bot.py               # ABConsoleBot 类（从 app.py 提取）
│   ├── data_manager.py      # DataManager 类
│   └── user_handler.py      # UserRequestHandler 类
├── handlers/                # 命令处理器
│   ├── __init__.py
│   ├── commands.py          # /start, /help 等基础命令
│   ├── market.py            # 市场数据查询
│   ├── ranking.py           # 排行榜相关
│   ├── snapshot.py          # 单币快照
│   ├── ai.py                # AI功能
│   └── admin.py             # 管理员命令
├── utils/                   # 工具函数
│   ├── __init__.py
│   ├── text.py              # 文本处理（已创建）
│   ├── keyboard.py          # 键盘构建
│   ├── time.py              # 时间处理
│   └── validation.py        # 输入验证
├── services/                # 业务逻辑层
│   ├── __init__.py
│   ├── card_service.py      # 卡片服务
│   ├── signal_service.py    # 信号服务
│   └── ai_service.py        # AI服务
└── config.py                # 配置管理
```

#### 迁移步骤

1. **提取工具函数**（低风险）
   - 将 `_normalize_symbol_ascii`, `_resolve_symbol_input` 等移到 `utils/text.py`
   - 将时间相关函数移到 `utils/time.py`
   - 验证相关移到 `utils/validation.py`

2. **提取处理器**（中风险）
   - 每个命令处理器作为独立函数
   - 使用装饰器注册到主 bot

3. **重构主类**（高风险）
   - 逐步将 `ABConsoleBot` 的方法移到各模块
   - 保持向后兼容

### Phase 3: 高级优化（下季度）

1. **引入消息队列**
   - 替换文件轮询机制
   - 使用 Redis Pub/Sub

2. **添加监控**

   - 分布式追踪

3. **性能优化**
   - 连接池调优

## 📝 Docker Compose 更新

### 健康检查配置

```yaml
services:
  data-service:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8081/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    restart: unless-stopped

  signal-service:
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8083/health"]
      interval: 30s
      timeout: 10s
      retries: 3
```

### 依赖管理

```yaml
services:
  signal-service:
    depends_on:
      data-service:
        condition: service_healthy  # 等待 data-service 健康后才启动
```
